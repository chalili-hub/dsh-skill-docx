# 报告骨架与写作规范

## 1. 标准骨架

```
封面：课程名 / 报告标题 / 副标题 / 姓名 学号 / 实验日期
一、实验目的                    分条写，动词开头（了解/掌握/编写/观测/解释）
二、实验环境
    2.1 软硬件环境              用表：平台、系统、工具与版本（版本号必须真实）
    2.2 环境搭建                分小节，每节「说明文字 + 命令代码块」
三、实验内容一：<第一个任务>
    3.1 编写/设计
    3.2 编译与转换              命令 + 原始输出（readelf/objdump/转换结果）
    3.3 运行/仿真               命令 + 结束状态
    3.4 结果分析                图 + 逐条解读
四、实验内容二：<第二个任务>
    （同上结构）
五、实验内容三：<解释题 / 核心分析>   ← 通常分值最高，篇幅最大
    5.1 <阶段一>                观察值 → 含义 → 支撑结论
    5.2 <阶段二>
    5.3 <阶段三>
    5.4 <规律/序列>
    5.5 <与规范/约定的对应>
六、实验结论                    分条回扣实验目的，每条都落到具体数值
附录 A  完整命令清单
附录 B  <关键信号 / 数据结构> 对照表
附录 C  数据获取方法说明        （自研脚本要写清楚，保证可复现）
```

## 2. 各章写法

### 实验目的
4~5 条，覆盖：架构/原理认知、环境与工具链搭建、动手实现、观测与分析、规范理解。

### 实验环境
- 版本号**必须来自实际命令输出**（`--version`），不要写"最新版"。
- 环境搭建每小节的结构固定：**为什么需要 → 怎么做（命令）→ 结果是什么（关键输出）**。

### 实验内容 / 步骤
- 命令**原样给**，包括 `-nostdlib`、`-Ttext=0x200` 这类关键参数；并在正文里解释每个关键参数的作用。
- 原始输出用代码块原样贴（ELF 头、反汇编、仿真结束信息）。
- 反汇编这类长输出，**后面补一张"关键地址对照表"**（地址 / 机器码 / 汇编 / 功能说明），把读者引到重点行。

### 结果分析（报告的主体）
按**时间/阶段**推进，每步三段式：

1. **观察**：某个信号/量在某时刻是什么值（给出具体数）。
2. **含义**：这个值在体系里代表什么（对照源码常量、协议定义、调用约定）。
3. **支撑**：它如何推出下一步或支撑结论。

要求里如果点名了某个现象或某条指令，**必须单独开小节**逐拍讲透，并给出"对答案"的比对。

### 结论
- 分条，每条挂具体数值（`x5 = 0x0C`、`PC 保持 3 拍`），不要写"实验成功""收获很多"这类空话。
- 最后一条可以写方法论层面的收获（工具链、调试手段、原理理解）。

### 附录
- 命令清单要能**直接复制执行**，按阶段分节加注释。
- 自研脚本/非常规方法必须写进附录 C，说明做了什么、为什么这么做、怎么复现——这既保证可复现，也解释了为什么报告里的图不是截图。

## 3. 图表规范

| 类型 | 要求 |
| --- | --- |
| 图 | 必须有编号 + 标题（图 N 说明文字），标题写"这张图证明了什么" |
| 表 | 必须有编号 + 标题（表 N-1 说明文字），表头加底纹，列宽固定 |
| 代码块 | 等宽字体 + 浅灰底纹，**原样**不转述；配"代码 N-M 说明" |
| 正文引用 | 图/表/代码编号必须与正文一一对上（生成后 grep 校验一遍） |

图的绘制要求：
- 数字波形：横轴标时钟周期，值用十六进制标在波形内，行标签用"信号名 = 含义"的形式。
- 中文图表：`font.sans-serif = ['Microsoft YaHei','SimHei',...]`，
  **含中文的文本不要设 `family="monospace"`**（会出方框）。
- 刻度/网格要能让人读出周期位置；不要把 20 个信号挤在一张图里。

## 4. 语言与体例

- 人称：以"本次实验/我们/可以看到"叙述，避免第一人称口语。
- 数字一律给**十六进制 + 十进制**对照（`0x0C（即 12）`），硬件类报告尤其重要。
- 术语首次出现给中英文（"取指（Fetch）阶段"）。
- 代码/信号名用等宽字体，与正文区分。
- **不要编造"心得体会"式的空话**；有失败与排查就写进"问题与解决"，它比空话有价值。

## 5. 交付前自检清单

- [ ] 报告里每个数值都能在 `数据/` 里找到出处
- [ ] 要求文档给出的"对答案"字段逐条比对通过
- [ ] 图/表/代码编号与正文引用一致
- [ ] 封面占位项（姓名等）已标注给用户去填
- [ ] 未完成/受限的环节已在报告中说明原因与替代方案
- [ ] 已导出 PDF 并逐页看过（字体、图、表、分页）
- [ ] 配套材料目录 + README 已就位；临时文件已清理
